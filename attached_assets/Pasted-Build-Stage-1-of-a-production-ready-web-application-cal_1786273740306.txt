Build Stage 1 of a production-ready web application called "Payroll Portal".

IMPORTANT:
This is a NEW, INDEPENDENT payroll application. Do NOT modify, connect to, or make assumptions about any existing school/fee portal at this stage.

The application will eventually be hosted on a subdomain such as:
payroll.<existing-domain>.com

The existing school fee portal and its payment/WhatsApp systems must remain completely untouched.

==================================================
PROJECT OBJECTIVE
==================================================

Create the foundation for a payroll management web application that will later:

1. Accept payroll Excel files.
2. Generate individual employee payslip PDFs.
3. Store payroll history.
4. Generate secure payslip links that expire after 7 days.
5. Send payslip notifications through the existing Meta WhatsApp Business/Cloud API.
6. Use the existing approved Meta WhatsApp template:
   statement_available_1

DO NOT implement Excel processing, PDF generation, WhatsApp integration, or statutory reports in Stage 1.

Stage 1 is only the foundation.

==================================================
TECHNOLOGY
==================================================

Choose a modern, stable full-stack architecture that works well natively on Replit.

Requirements:

- Responsive web application
- Desktop-first admin interface but fully usable on mobile
- Secure backend/API
- PostgreSQL database
- Proper server-side authentication
- Environment variables/secrets for all sensitive configuration
- No secrets hard-coded in source code
- Clean modular architecture so later stages can be added without restructuring the application
- Use TypeScript wherever practical
- Use a modern component-based frontend
- Use a clean professional UI suitable for a school/business payroll system

Do NOT introduce unnecessary frameworks or services.

Prefer Replit's native PostgreSQL/database facilities where appropriate so the application remains easy to develop and deploy on Replit.

==================================================
STAGE 1 FEATURES
==================================================

### 1. Authentication

Create secure admin authentication.

Requirements:

- Login page
- Email/username + password authentication
- Secure password hashing
- Secure session handling
- Logout
- Protected application routes
- Unauthenticated users must not be able to access the dashboard
- Do not expose passwords or authentication secrets in the frontend
- Do not create public registration

Initially this is an ADMIN-ONLY application.

Design the authentication architecture so employee accounts can potentially be added later, but DO NOT implement employee login in Stage 1.

Create a secure way to establish the initial administrator account during deployment/setup.

Do not put a default administrator password directly into source code.

==================================================
2. DATABASE FOUNDATION
==================================================

Create the PostgreSQL database schema needed for Stage 1.

At minimum create:

### users
Fields should include appropriate fields such as:

- id
- name
- email
- password_hash
- role
- is_active
- created_at
- updated_at
- last_login_at

Role should initially support:

- ADMIN

Structure the schema so additional roles can be added later.

### company_settings

Create a single company/settings record containing:

- id
- company_name
- logo
- address
- phone
- email
- website
- created_at
- updated_at

Only company_name and logo are mandatory for Stage 1.

For the logo, use an appropriate storage approach rather than storing a huge image directly in the database.

The architecture must allow the logo to be changed later by an administrator.

Do NOT hard-code the company name.

==================================================
3. ADMIN SETTINGS
==================================================

Create an Admin Settings page.

The administrator must be able to:

- Change company name
- Upload/change company logo
- Remove the existing logo
- Save changes
- See a preview of the logo
- See the current company name

Changes should be stored in the database/storage and persist after logout/reload.

Validate uploaded logo files.

Accept common image formats such as:
- PNG
- JPG/JPEG
- WebP

Set a sensible maximum file size.

Do not allow arbitrary executable files to be uploaded.

==================================================

Create a clean admin dashboard.

At this stage it should be a foundation/shell rather than a fully functional payroll dashboard.

Include:

Sidebar/navigation:

- Dashboard

- Payslips
- Settings

The pages/modules other than Dashboard and Settings can initially show a clean "Coming in next stage" placeholder.

Create a clean empty-state design rather than fake data.

7. SECURITY REQUIREMENTS
==================================================

Implement security from the beginning.

At minimum:

- Passwords must be securely hashed
- Authentication must be server-side
- Protected API endpoints
- Validate all user input
- Validate uploaded files
- Prevent unauthorized database access
- Do not expose sensitive environment variables to the browser
