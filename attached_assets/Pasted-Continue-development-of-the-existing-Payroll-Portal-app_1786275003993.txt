Continue development of the existing "Payroll Portal" application.

IMPORTANT:
Stage 1 has already been built.

DO NOT rebuild the application from scratch.
DO NOT replace the existing authentication system.
DO NOT modify unrelated Stage 1 functionality.

First inspect the existing codebase, database schema, authentication implementation, company settings, audit logging and UI structure. Build Stage 2 on top of the existing architecture.

==================================================
STAGE 2 OBJECTIVE
==================================================

Implement:

1. Employee Master
2. Payroll Run management
3. Payroll Excel upload
4. Excel column mapping
5. Payroll data preview
6. Validation and error reporting
7. Payroll import confirmation
8. Payroll history foundation

The payroll Excel file will contain employee salary/payroll information that is ALREADY CALCULATED.

IMPORTANT:

The application is NOT responsible for calculating salary, PF, ESI, TDS or other statutory deductions at this stage.

The Excel file is the source of the final payroll figures.

The application must import, validate and store the figures accurately.

==================================================
1. EMPLOYEE MASTER
==================================================

Create a fully functional Employees module.

Navigation:

Employees

The employee list should display:

- Employee ID
- Employee Name
- Mobile Number
- Designation
- Branch
- Joining Date
- Status
- Actions

Support:

- Add employee
- Edit employee
- View employee
- Activate/deactivate employee
- Search employees
- Filter by branch
- Filter by active/inactive status

Do NOT permanently delete employees from the database.

Use an Active/Inactive status instead.

This is important because historical payroll records must remain associated with employees even after they leave the organization.

==================================================
2. EMPLOYEE DATA MODEL
==================================================

Create/extend the employee database table with appropriate fields.

At minimum:

- id
- employee_code
- employee_name
- mobile_number
- email
- designation
- branch
- joining_date
- status
- created_at
- updated_at

Employee code must be unique.

Mobile number should be stored in a normalized format suitable for future WhatsApp API use.

Do not assume that every employee has an email address.

Mobile number should be optional at the employee-master level, but the system must flag it as a warning when WhatsApp delivery is later required.

==================================================
3. EMPLOYEE MASTER VALIDATION
==================================================

When adding/editing employees:

Required:

- Employee ID/code
- Employee name

Validate:

- Employee ID is unique
- Employee name is not empty
- Mobile number format if provided
- Email format if provided
- Joining date if provided

Show user-friendly validation messages.

Do not expose database errors directly.

==================================================
4. PAYROLL RUNS
==================================================

Create a Payroll Runs module.

Each uploaded payroll Excel file represents one payroll run.

Create a payroll_runs table containing appropriate fields such as:

- id
- payroll_month
- payroll_year
- original_file_name
- uploaded_by
- upload_timestamp
- employee_count
- total_gross
- total_deductions
- total_net
- status
- created_at
- updated_at

Payroll run status should support at least:

- DRAFT
- VALIDATED
- IMPORTED
- CANCELLED

Do not generate payslips yet.

==================================================
5. PAYROLL EXCEL UPLOAD
==================================================

Create:

Payroll → Upload Payroll

Allow the administrator to upload:

- .xlsx
- .xls

Do not accept arbitrary file types.

Validate reasonable file size limits.

The original uploaded filename should be recorded.

The application should NOT automatically import the data immediately after upload.

Instead use this workflow:

Upload
↓
Read Excel
↓
Detect worksheet(s)
↓
Select worksheet if multiple worksheets exist
↓
Detect header row
↓
Map columns
↓
Preview
↓
Validate
↓
Administrator confirms
↓
Create Payroll Run
↓
Store payroll records

==================================================
6. EXCEL COLUMN MAPPING
==================================================

Do NOT assume that the Excel file always uses exact column names.

Create a column-mapping interface.

For example, the Excel file might contain:

Employee ID
Employee Name
Basic
DA
HRA
Gross Salary
PF
ESI
TDS
Other Deductions
Net Salary

But another month may use slightly different names.

The application should:

1. Read the Excel headers.
2. Suggest mappings based on header names.
3. Allow the administrator to manually change mappings.
4. Clearly indicate required fields.
5. Remember the last successful mapping for future uploads where practical.

At minimum, the following payroll fields should be supported:

IDENTIFICATION:

- Employee ID
- Employee Name

EARNINGS:

- Basic
- DA
- HRA
- Other Earnings
- Gross Salary

DEDUCTIONS:

- PF
- ESI
- TDS
- Other Deductions

FINAL:

- Net Salary

The system must also allow additional payroll columns to exist in the Excel file without breaking the import.

Do not silently discard unknown columns.

Show them as "Additional fields" or "Unmapped columns".

==================================================
7. IMPORTANT: FLEXIBLE PAYROLL COLUMNS
==================================================

The payroll Excel may contain additional salary components.

Examples:

- Conveyance
- Medical Allowance
- Special Allowance
- Bonus
- Incentive
- Professional Tax
- Loan Deduction
- Advance
- Other Deduction
- Arrears
- Overtime
- Leave Deduction

The system should NOT reject an Excel file simply because additional columns exist.

Store additional payroll components in a flexible structure so they can later be displayed on the payslip.

Design the data model so Stage 3 can use these components when generating PDFs.

Do not hard-code the final payslip structure yet.

==================================================
8. EMPLOYEE MATCHING
==================================================

During payroll import, match payroll records to Employee Master using:

PRIMARY:
Employee ID/code

Do NOT match primarily by employee name.

If Employee ID is missing or doesn't match an existing employee:

Show a clear validation error.

Example:

"Employee ID 1045 was not found in Employee Master."

Do NOT automatically create an employee based on an Excel row.

The administrator should be able to:

- Go back and add the employee
- Correct the Excel file
- Cancel the import

Do not silently create employees.

==================================================
9. DUPLICATE DETECTION
==================================================

Detect:

- Duplicate Employee IDs within the uploaded Excel
- Employees appearing more than once in the same payroll run
- Duplicate payroll run for the same month/year, if applicable

Do not silently overwrite existing payroll data.

If a payroll run already exists for the same month/year:

Show a clear warning and require explicit administrator confirmation before replacing/re-uploading.

Do not delete the old payroll run automatically.

==================================================
10. PAYROLL PERIOD
==================================================

The administrator must select:

Payroll Month
Payroll Year

during upload/import.

Do not rely only on the filename.

Example:

July 2026

The selected payroll period must be stored with every payroll record.

11. PREVIEW
==================================================

After mapping columns, show a preview table before importing.

Display:

- Employee ID
- Employee Name
- Earnings
- Deductions
- Gross Salary
- Net Salary
- Validation status

Allow horizontal scrolling for wide payroll files.

Do not make the interface unusable when there are many payroll columns.

==================================================
12. VALIDATION
==================================================

Validate each row before import.

Examples:

ERRORS:

- Missing Employee ID
- Employee ID not found
- Missing Employee Name
- Duplicate Employee ID
- Invalid numeric salary value
- Invalid payroll period
- Invalid file
- Required column not mapped

WARNINGS:

- Employee has no mobile number
- Employee has no email
- Optional salary component is blank
- Unmapped Excel column exists

Important distinction:

ERROR = payroll cannot be imported until fixed.

WARNING = administrator can continue after reviewing.

Show a clear summary:

Example:

125 employees detected

118 valid
5 warnings
2 errors

The Import button must remain disabled while blocking errors exist.

==================================================
13. NUMERIC DATA
==================================================

Salary amounts must be handled safely.

Do NOT use floating-point arithmetic for stored monetary values where avoidable.

Use an appropriate decimal/numeric database type.

Accept common Excel formats such as:

25000
25,000
25000.00

Normalize them internally.

Do not alter the actual salary values during import.

The imported figures must remain exactly as provided, subject only to formatting/normalization.

==================================================

Maintain all Stage 1 security practices.

Important:

- Payroll data is sensitive.
- Uploaded Excel files must not be publicly accessible.
- Payroll records must require authenticated admin access.
